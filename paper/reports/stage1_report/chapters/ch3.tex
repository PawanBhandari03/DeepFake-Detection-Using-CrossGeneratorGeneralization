\chapter{Software Requirements Specification}
The requirements follow the structure of IEEE Std 830-1998 (continued in ISO/IEC/IEEE 29148). The full specification is kept in the project repository; this chapter gives its main parts.

\section{Product Perspective and Users}
The system is a new, self-contained product with three analysis pipelines (image, video, document) that share one scoring engine and one web interface. Models are trained offline on free cloud GPUs; the web application only loads the trained files.

\section{Assumptions and Dependencies}
\begin{itemize}
  \item Public datasets remain available. GenImage and OpenFake are public; FaceForensics++, Celeb-DF and DocTamper need access requests.
  \item The pretrained CLIP weights remain downloadable.
  \item Uploaded files are not deliberately adversarial beyond normal editing and compression.
  \item Free hosting (Streamlit Community Cloud) remains available, with a memory limit of about 2.7~GB.
\end{itemize}

\section{External Interface Requirements}
\begin{itemize}
  \item \textbf{User interface:} a web page with drag-and-drop upload, a result card with the Trust Score and a colour-coded verdict, a heatmap, an explanation, tabs for technical evidence, and pages for the cross-generator results and a ``How it works'' description.
  \item \textbf{Hardware interface:} a standard laptop or server CPU for inference; a GPU is optional and is used only for training.
  \item \textbf{Software interface:} Python, PyTorch, open\_clip, Pillow (with HEIC support), scikit-learn, Streamlit; later OpenCV/FFmpeg, Tesseract and PyMuPDF for video and documents.
  \item \textbf{Communication interface:} HTTPS between the browser and the server; GitHub for the code, with automatic redeployment when the main branch changes.
\end{itemize}

\section{Non-functional Requirements}
\textbf{Performance.} An image should be analysed in about five seconds on a laptop CPU (the first prototype needed about ten); server memory must stay below 2.7~GB (peak use of the prototype is about 1.5~GB).

\textbf{Safety.} Probabilities must be calibrated, uncertain cases go to \emph{Needs Human Review}, and no verdict is shown without evidence. The Trust Score is a screening aid and not a forensic proof.

\textbf{Security and privacy.} Uploads are processed in temporary memory and are never stored or used for training. Files are parsed and never executed, and an image-size limit protects against decompression attacks.

\textbf{Software quality attributes.}
\begin{itemize}
  \item \emph{Reliability:} every verdict has evidence; invalid files are rejected with a message.
  \item \emph{Usability:} colour-coded verdicts, plain-language explanations and the result on one screen.
  \item \emph{Maintainability:} independent analysers behind one evidence interface, so that a model can be replaced without changing the application.
  \item \emph{Portability:} runs on Windows and Linux, CPU only.
\end{itemize}

\section{Constraints}
Only free and open-source tools are used and the budget is zero. Datasets are used under their research licences. The academic timeline is 26 weeks, from September 2026 to March 2027.
